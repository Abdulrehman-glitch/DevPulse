# Security policy

## Supported versions

No public DevPulse version is currently supported. This private staging history is preparing `0.3.0-alpha.1`; historical versions through `v0.2.0-beta.1` remain in the private pre-public archive and do not receive public fixes from this repository.

After the first public prerelease, this table will identify supported release lines and security-update expectations.

## Reporting a vulnerability

Do not disclose a suspected vulnerability, credential, exploit detail, or affected user information in an ordinary GitHub issue, discussion, pull request, or public channel.

GitHub private vulnerability reporting is not claimed to be active during private staging. It will be enabled and verified as an immediate public-launch gate. Once active, use the repository’s **Security → Report a vulnerability** flow.

While the repository remains private, only already-authorized staging participants can report through the existing private repository channel to the maintainer. There is no public interim intake address and no fabricated security email. If you do not already have private access, wait for the verified public security-reporting route rather than publishing details.

The maintainer will acknowledge, triage, reproduce, coordinate remediation, and decide disclosure timing. Reports should include affected version, impact, prerequisites, minimal reproduction, and any suggested mitigation, while avoiding unnecessary personal data or live credentials.
